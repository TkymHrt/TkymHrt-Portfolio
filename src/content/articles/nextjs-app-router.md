App Router を使った実装で最初に迷ったのは、Server Component と Client Component の境界でした。すべてを同じ書き方に寄せるのではなく、画面に必要なデータと操作を先に分けると判断しやすくなりました。

## 境界は操作から考える

初期表示に必要なデータはできるだけサーバー側で準備し、ブラウザの状態やイベントが必要な範囲だけを Client Component にします。境界を小さく保つことで、送信する JavaScript と状態管理の両方を抑えられます。

## ローディングも画面設計に含める

データ取得の途中を単なる待ち時間にせず、どの範囲が更新されているか分かる表示を用意します。完成時の画面だけでなく、読み込み・空・失敗の状態を最初から並べて考えることが大切でした。

## まとめ

新しい API を覚えること以上に、ページの責務を説明できる単位へ分けることが重要でした。機能を追加するときも、サーバーとクライアントの境界を意識して見直していきます。
