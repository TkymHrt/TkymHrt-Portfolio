Prisma と tRPC を組み合わせると、データベースから画面まで TypeScript の型をつなげられます。一方で、型が共有できることと、責務を一つにまとめることは別です。

## 入力を境界で検証する

画面から届く値は API の入り口で検証し、その先では検証済みの値だけを扱います。エラーは利用者が次に何をすればよいか分かる粒度へ変換して返します。

## 問い合わせを用途で分ける

大きな汎用クエリを一つ作るより、画面で必要な情報に合わせた小さな問い合わせへ分けます。取得項目が明確になり、画面側の条件分岐も減らせました。

## まとめ

型安全は設計を置き換えるものではなく、設計した境界を守りやすくする道具です。データの責務と利用者へ見せるエラーを先に決めると、便利さを活かしやすくなります。
